# Cloudmesh AI VPN Sample Scripts

This directory contains sample shell scripts to help users establish VPN connections using `openconnect` and `vpn-slice`, mirroring the logic implemented in the `cloudmesh-ai-vpn` project.

## Available Scripts

| Script | OS | Mode | Description |
| :--- | :--- | :--- | :--- |
| `connect_linux.sh` | Linux | Background | Connects to VPN in background using password authentication. |
| `connect_osx.sh` | macOS | Background | Connects to VPN in background using password authentication. |
| `connect_linux_2fa.sh` | Linux | Interactive | Connects to VPN interactively to support Two-Factor Authentication (2FA). |
| `connect_osx_2fa.sh` | macOS | Interactive | Connects to VPN interactively to support Two-Factor Authentication (2FA). |
| `disconnect.sh` | Both | - | Gracefully and forcefully terminates all `openconnect` and `vpn-slice` processes. |
| `s.sh` | Linux | Background | Minimalist script for full-tunnel connection. |
| `s-split.sh` | Linux | Background | Minimalist script for split-tunnel connection. |

## Prerequisites

### 1. Account Registration
Before using the VPN, you must register your device. Please visit:
[https://cloud.securew2.com/public/82116/limited/?device=Unknown](https://cloud.securew2.com/public/82116/limited/?device=Unknown)

**How to find your MAC address (Linux):**
To register your device, you may need your MAC address. You can find it by running:
```bash
ip link show
```
Look for the `link/ether` line (e.g., `00:11:22:33:44:55`) for your active network interface (usually `eth0` or `wlan0`).

### 2. Software Dependencies
Ensure you have the following tools installed:

### macOS
Install via Homebrew:
```bash
brew install openconnect vpn-slice
```

### Linux (Ubuntu/Debian)
Install via apt:
```bash
sudo apt update
sudo apt install openconnect
```
*Note: `vpn-slice` may need to be installed manually from [its GitHub repository](https://github.com/dlt-columbia/vpn-slice).*

## Usage

### 1. Configuration
Open the desired script and update the following variables at the top of the file:
- `VPN_HOST`: The VPN gateway address (e.g., `uva-anywhere-1.itc.virginia.edu`).
- `VPN_USER`: Your organization username.
- `VPN_TARGET_IP`: The IP range for split-tunneling (e.g., `128.143.0.0/16`).

### 2. Running the scripts
Make sure the scripts are executable:
```bash
chmod +x *.sh
```

Run a connection script:
```bash
./connect_osx.sh
# OR for 2FA
./connect_osx_2fa.sh
```

### 3. Disconnecting
To terminate the connection and clean up routing:
```bash
./disconnect.sh
```

## Base Scripts (s.sh & s-split.sh)

The `s.sh` and `s-split.sh` scripts are minimalist, working base versions used to verify core connectivity logic. While the `connect_*.sh` scripts provide more features (debugging, OS detection, validation), these base scripts offer a direct approach:

- **`s.sh`**: Establishes a **Full Tunnel** connection. All network traffic is routed through the VPN.
- **`s-split.sh`**: Establishes a **Split Tunnel** connection using `vpn-slice`, routing only specific university IP ranges through the VPN.

Both base scripts rely on pre-extracted unencrypted PEM certificates located in `~/.ssh/`.

## Technical Notes

- **Background vs Interactive**: The standard `connect_*.sh` scripts use the `-b` flag to run the VPN in the background. However, 2FA requires an interactive terminal to handle prompts (like Duo Push), so the `*_2fa.sh` scripts run in the foreground.
- **Split-Tunneling**: These scripts use `vpn-slice` to ensure only traffic destined for the `VPN_TARGET_IP` range is routed through the tunnel, preventing your entire internet connection from being routed through the VPN.
- **Sudo**: The scripts use `sudo` as `openconnect` requires root privileges to create the tun interface and modify routing tables.

## Makefile Shortcuts

The included `Makefile` provides convenient shortcuts for common tasks:

- `make on`: Starts the interactive 2FA connection process.
- `make off`: Disconnects from VPN and cleans up processes.
- `make make-install`: Installs dependencies on Linux/Pi (handles PEP 668).
- `make extract`: Extracts PEM certificates from `~/.ssh/luc.p12`.
    - **Interactive**: `make extract`
    - **Non-interactive**: `make extract PASS=your_p12_password`
- `make cp`: Copies the sample directory to the remote machine `luc`.

### Using Extracted Certificates
If you encounter errors decrypting the `.p12` file directly in `openconnect`, you can use the files generated by `make extract` instead:

```bash
sudo openconnect -c certificate.pem -k private-key-unencrypted.pem [other-options] <server>
```
This bypasses the need for `openconnect` to decrypt the PKCS#12 container at runtime.

## Troubleshooting "Login failed"

If you see `Login failed` in the logs after entering your password:

1. **Verify Registration**: Your account must be registered for VPN access. If you haven't registered your device, please do so here: [VPN Registration Link](https://cloud.securew2.com/public/82116/limited/?device=Unknown).
2. **Check Credentials**: Ensure you are using your full University VPN password.
3. **Check Account Status**: Verify that your account is not locked or that your password has not expired.
4. **MAC Address**: Ensure the MAC address of the machine you are connecting from matches the one registered in the VPN portal.
5. **Full Tunneling**: If you have trouble accessing specific resources, try disabling split-tunneling by setting `SPLIT_VPN=false` in the connection script.
